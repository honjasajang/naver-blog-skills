# 성적표 — 우리 접속을 거르고, 검색에서 온 것만 센다

## 0. 가게 파일을 먼저 읽는다
`가게.블로그ID` · `폴더.크롬포트`(예: 9222. 비어 있으면 통계 부분은 못 잰다 — 아래 1번) · `폴더.초안`(올린-글 폴더의 `발행.json`으로 발행일을 안다) · 네이버 API 키(`.env`, 색인·순위에 필요).

## 1. 통계는 자기 크롬으로만 읽는다
네이버는 **로그인한 주인의 조회는 안 센다.** 그런데 새 브라우저(비로그인)로 자기 글을 열면 외부 방문자로 잡힌다 — 한 업종에서 확인차 글을 대여섯 번 열었던 날 조회가 평소 5~9에서 23으로 뛰었다. 그래서:
- 통계 화면은 **사용자가 로그인해 둔 크롬**에 붙어서(디버그 포트) 읽는다. 크롬을 포트와 함께 띄우는 법은 `docs/설치안내.md` 「성적표용 크롬」.
- 그 크롬으로 **검색·자기 글 열기는 하지 않는다**(주인 계정의 기계 활동은 스팸 사례에 든다). 통계 화면만.
- 하루 한 번만 돌린다.

## 2. 실행
```
node skills/blog-scoreboard/scripts/성적.mjs                 # 최근 7일 조회(갈래별) + 들어온 검색어 + 글별 색인
node skills/blog-scoreboard/scripts/성적.mjs --기간=14       # 최대 15일
node skills/blog-scoreboard/scripts/성적.mjs --순위 "젤네일 가격" "젤네일 지속"
```

## 3. 읽는 법 (잣대)
- **성과는 「검색」 칸으로만 말한다.** 「전체」엔 우리가 주소로 바로 연 것(출처 없음)과 블로그 안 이동이 섞인다. 출처 없음이 0이 아닌 날은 우리가 연 날이다 — 🔴 표시.
- **홈판**(네이버 앱 첫 화면 추천)은 검색과 따로 말한다. 진짜 사람이지만 추천이 끊기면 같이 끊긴다.
- 글을 올린 날(⚠️)은 확인 접속이 섞일 수 있다 — 그날 숫자만으로 성과를 말하지 않는다.
- **색인과 순위는 다른 문제다.** 색인됐는데 73위라 조회 0인 글이 있다. 색인은 「제목 그대로 검색 → 안 잡히면 본문 문장 둘을 따옴표로」 두 방법으로 본다(한쪽만 보면 틀린다).
- **순위는 블로그 탭 기준(검색 API)**이다. 사람 화면(통합검색 첫 화면)과 다르고, 네이버는 같은 시각에 두 가지 순위를 번갈아 주기도 한다 — 한 번 값으로 단정하지 않는다.

## 4. 출력 꼴 (고정)
```
■ 일별 조회수 (최근 N일 · 오늘은 지금까지) — 글별 숫자는 검색에서 온 것만
   날짜   전체  검색  홈판  안  출처없음   (🔴 우리 접속 · ⚠️ 올린 날)  글별 검색 유입
■ 들어온 검색어 (날짜별)
■ 색인 (제목 → 본문 문장) — 공개 n편 중 색인 m편
■ 블로그 탭 순위 (검색 API 기준) — 사람 화면과 다를 수 있다
■ 못 본 것
```

## 5. 한계
- 통계 자료 주소(blog.stat.naver.com)는 공개 API가 아니라 네이버가 바꾸면 깨진다. 깨지면 「못 봄」으로 적고 통계 화면 캡처를 사람에게 부탁한다.
- 색인·순위는 검색 API라 하루 25,000회 안에서. API 키 없으면 그 두 절은 건너뛴다.
- 글 목록은 `올린-글/*/발행.json`(사람이 적은 주소)으로 안다. 비공식 글 목록 엔드포인트는 쓰지 않는다.
