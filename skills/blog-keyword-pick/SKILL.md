# 검색어 고르기 — 자리 × 수요 × 가족

네이버 블로그 글 하나가 사람을 데려오려면 세 가지가 **동시에** 맞아야 한다.
**자리**(상위 10이 큰 블로그로 차 있지 않은가) · **수요**(그 검색어를 실제로 몇 명이 치나) · **가족**(그 검색어 한 개가 아니라 변형 전체를 한 글이 먹을 수 있나).
하나만 보면 틀린다 — 자리만 보면 「이겨도 하루 2회」짜리를 고르고, 수요만 보면 못 뚫는 곳을 고르고, 가족을 빼면 한 자리만 먹는다.

## 0. 가게 파일을 먼저 읽는다

`.agents/blog-shop.md`를 읽는다(없으면 `.agents/blog-shop.example.md`를 복사해 만들라고 안내하고, **업종·씨앗 검색어·블로그 ID**만 먼저 받는다). 이 skill이 쓰는 칸:
- `검색어.씨앗` · `검색어.가족` · `검색어.우리글`
- `수요.앵커`(큰쪽·작은쪽) · `수요.환산`
- `기준치.자리.약한자리최소`(기본 6/10) · `기준치.레퍼런스.이웃최대`(기본 300)
- `폴더.자료`(측정값이 쌓이는 곳)

가게 파일에 있는 값을 사용자에게 다시 묻지 않는다. 없는 칸만 묻는다.

## 1. 절차

1. **씨앗 → 검색어 사전**: 가게 파일의 씨앗마다 사용자가 아는 변형(「○○ 뜻」「○○ 여자」「○○ 2개」「2027 ○○」)을 모은다. 자동완성 긁기는 **하지 않는다**(약관). 변형은 사용자·가게 파일·이미 잰 자료에서만.
2. **수요 재기**: `scripts/수요재기-api.mjs <검색어…>` — 네이버 데이터랩 **공식 API**. 한 조회에 앵커 둘 + 새 검색어 셋. 결과는 `큰쪽 앵커 = 100`인 지수. 하루 1,000회 한도이니 한 번에 30개 안쪽.
3. **자리 재기**: `scripts/자리-api.mjs <검색어…>` — 네이버 검색 **공식 API**(블로그)로 상위 10의 블로그 주소를 받는다. 「작은 블로그」 판정(이웃 수)은 API에 없다 → `자료/블로그.json`에 이웃 수가 있는 블로그만 판정하고, 없으면 **「미판정」으로 표시**한다. 사용자에게 손으로 이웃 수를 넣는 길을 안내한다(블로그 메인에 보임).
4. **타율 표**: `scripts/타율.mjs` — 가족별로 수요 합·뚫을 수 있는 검색어 수·우리 글 유무를 한 표로. 여기서 고른다.
5. **추천**: 아래 출력 꼴로. 추천은 **가족** 단위다(검색어 하나가 아니라). 수요가 환산 지수 아래면 「쓰더라도 하루 2회쯤」이라고 적는다.

## 2. 판정 규칙 (가게 파일 기준치가 우선)

- 자리: 상위 10 중 「이웃 < 이웃최대」가 `약한자리최소` 이상이면 뚫을 수 있는 자리. 미판정 블로그는 세지 않고 **분모에서도 뺀다**(0/0을 0/10으로 읽지 않는다).
- 수요: 앵커 환산 지수. `환산.지수` 아래면 경고. 절대 문턱은 두지 않는다 — 가게마다 다르다.
- 가족: 가족 안 검색어 수와 수요 합. **우리 글이 이미 있는 가족**은 「덮기 늘리기」로, 없는 가족은 「새 글」로 나눈다.
- 최고 1개로 판정하지 않는다. 가족 안 검색어 몇 개 중 몇 개가 뚫리는지(분포)로 말한다.

## 3. 도구의 한계 — 결과에 꼭 적는다

- 검색 API의 블로그 결과는 **휴대폰 통합검색 첫 화면과 다르다**(첫 화면은 인플루언서·AI 탭·동영상이 섞인다). 「블로그 탭 기준」이라고 명시한다. 첫 화면 짜임은 blog-reference-read가 사용자가 붙인 링크로 읽는다.
- 데이터랩 지수는 **상대값**이다. 절대 검색량이 아니다. 조회마다 최대가 100이라 앵커 없이 비교하면 틀린다.
- 데이터랩은 **최근 며칠은 비어 있을 수 있다** — 월 단위 12개월 평균을 쓴다.
- 이웃 수·방문 수는 API에 없다. 미판정은 미판정이라고 쓴다.
- 자동완성·통합검색 긁기는 이 skill이 하지 않는다. 그 기능을 요구하면 약관 때문이라고 말하고 대신 손 입력을 안내한다.

## 4. 출력 꼴 (고정)

```
■ 추천 가족: <가족명>  (새 글 / 덮기 늘리기)
  수요 합 <N>(큰쪽 앵커=100) · 뚫리는 검색어 <a>/<b> (미판정 <c>) · 우리 글 <있음/없음>
  이 글 하나가 받을 검색어: <검색어 5~8개>
  예상: 지수 <x> → 하루 <y>회쯤 (가게 파일 환산 기준)

■ 다음 후보 2개  (같은 꼴로 짧게)

■ 재지 않은 것 / 한계
  - 블로그 탭 기준 · 상대값 · 미판정 <c>곳 · 수요 못 잰 검색어 <d>개
```

## 5. 사용자에게 물을 것 (가게 파일에 없을 때만)

- 업종과 손님이 치는 말 3~5개(씨앗)
- 이미 올린 글의 검색어(우리글)
- 네이버 API 키가 `.env`에 있는지(없으면 발급 안내 — 「사용 API」에 검색·데이터랩 둘)
