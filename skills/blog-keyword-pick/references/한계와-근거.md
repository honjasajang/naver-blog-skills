# 한계와 근거 — blog-keyword-pick

## 공식 API만 쓴다 (2026-10-30 문서 확인)
| | 데이터랩 검색어트렌드 | 검색(블로그) |
|---|---|---|
| 주소 | POST https://openapi.naver.com/v1/datalab/search | GET https://openapi.naver.com/v1/search/blog.json |
| 헤더 | X-Naver-Client-Id · X-Naver-Client-Secret | 같음 |
| 입력 | startDate(2016-01-01부터)·endDate·timeUnit(date/week/month)·keywordGroups ≤5(그룹당 keywords ≤20)·device/gender/ages 선택 | query·display(≤100)·start(≤1000)·sort(sim/date) |
| 출력 | results[].data[].period·ratio — **조회 안 최대가 100인 상대값** | items[].title·link·description·bloggername·bloggerlink·postdate, total |
| 한도 | 하루 1,000회 | 하루 25,000회 |

## 왜 이렇게 재나
- **상대값 환산**: 조회마다 최대가 100이라 조회끼리 비교하려면 같은 앵커를 매 조회에 끼워야 한다. 가게 파일 `수요.앵커`(큰쪽·작은쪽). 운세 업종 실측 예: 「도화살=100」, 「괴강살 37 = 8위 = 하루 2회」(2026-09-28)로 환산했다.
- **자리 × 수요 × 가족**: 2026-09-28 사고 — 자리(8~9/10)만 보고 세 편을 썼는데 수요가 29~57이었고(띠별운세 5,171), 글이 상위 글의 절반 길이에 한 글이 검색어 0자리였다. 그 뒤 「둘 다 재고, 가족을 통째로」로 바꿨다.
- **최고 1편 금지**: 검색어 하나에서 1위는 요행일 수 있다. 분포로 본다.

## 못 재는 것 (결과에 그대로 적는다)
1. **휴대폰 통합검색 첫 화면** — 검색 API는 블로그 탭이다. 첫 화면엔 인플루언서·AI 탭·동영상·지식iN이 섞여 순위가 다르다. 실측(2026-09-29): 블로그 탭 8위 글이 첫 화면엔 없었다.
2. **이웃 수·방문 수** — API에 없다. 블로그 메인에 보이는 값을 손으로 `자료/블로그.json`에 넣으면 판정한다. 미판정은 0으로 세지 않는다.
3. **절대 검색량** — 데이터랩은 상대값만 준다. 「하루 N회」는 가게 파일 환산 기준(우리 글이 실제로 몇 위에 몇 회 왔나)으로만 말한다.
4. **자동완성** — 긁지 않는다(네이버 약관). 변형은 사용자·가게 파일·이미 잰 자료에서.
